# Coherent Diffusion — P07 candidate install and live acceptance

**Status: integration candidate, NOT release-ready.** The ZIP includes Python modules and the locally rendered HTML editor, but actual Forge Neo SDXL / Anima Q4 / GPU acceptance has **not** been performed by this agent. P07 remains open pending these results. Do not replace an accepted stable extension with an untested candidate without taking a backup.

## Installation and rollback

1. Confirm Forge Neo is stopped. Back up any existing `extensions/coherent-diffusion` directory. Your saved editor drafts live in the browser profile, not inside the extension directory; export a CRF ZIP before changing browsers.
2. Extract `coherent-diffusion-P07-candidate.zip` **into** Forge Neo's `extensions/` directory. The resulting path should be `extensions/coherent-diffusion/scripts/coherent_diffusion.py`; do not nest the directory twice.
3. In the exact Python environment that launches Forge (for example the user's `.venv-neo`, **not** a separate `venv`), ensure `jsonschema`, `torch`, `Pillow` and Gradio are installed. The repo's `requirements.txt` pins jsonschema, but the extension intentionally reuses Forge's existing Torch/Gradio model environment. Do not replace or reinstall your working GGUF/Q4 loader. There are no CDN/frontend dependencies.
4. Restart Forge Neo. Open **Coherent Diffusion**. Generation uses Forge's shared `modules.call_queue.queue_lock`, calls the native `refresh_model_loading_parameters()` and `forge_model_reload()` using the checkpoint/encoder selected in Forge, then restores native model patcher objects on all exit paths. **No preliminary native txt2img generation should be needed**. Generation results/errors appear in the **Generate · loaded Forge checkpoint** panel under the full-width editor. If the tab fails to load, record the Forge log.
5. **Rollback:** stop Forge, remove `extensions/coherent-diffusion`, restore the original backup if any, and restart. No persistent Forge checkpoint/loader patch is intended. Retain exported CRF ZIPs.



## First full-resolution Anima/Q4 live success; unique-entity spatial anchor (P07 experimental)

**Operator-verified installed run, 2026-10-26:** The CyberRealistic Anima model with Forge-native Q4 GGUF Qwen text encoder and WAN tiled VAE generated a **2048×1536 full-resolution PNG**. Its server journal records 148 completed model predictions, successful tiled VAE decode, `generation_completed(success=true, elapsed_ms=1252773.42)` and `ui_png_saved(2048,1536)`. This constitutes **one verified working Anima/Q4 path**, not SDXL/LoRA/ControlNet acceptance or a tested performance guarantee. The returned full-size coastal image has no obviously large rectangular seams, but its generated solar highlight (~41% of image width) visibly misses the author-specified sun bbox at 71–84% of width. Do not characterize that output as validated spatial placement.

**Source cause and targeted repair:** Before this checkpoint, `_RegionalRunner.predict` routed all progressive `anchor` evaluations through one global text prompt, irrespective of CRF regions. Regions/entities were only consulted in full-resolution refinement, after global composition had formed. P07 now compiles **explicit count-one entity masks** (and only their referenced active regions) against the actual low-resolution patch-aligned anchor geometry. It blends native x0 predictions at the anchor with the global scene/style baseline while maintaining one synchronized global latent. The original CRF is unchanged; localized region LoRAs never load into the anchor; SDXL and Anima share the pure mask compiler, but neither gains a guaranteed object-position constraint. This feature increases anchor evaluation count per sampling step, which is reflected in progress upper-bound diagnostics.

**Compatibility and limitations:** Without an explicit count-one `entities` record, direct mode, or with no eligible active region, previous behavior remains unchanged. If global base weight is zero, anchored unique-entity blending is skipped and a `anchor_entity_fallback` diagnostic is recorded, preserving an otherwise valid full-canvas CRF. A unique entity also mentioned in the global scene prompt can still be created in an undesired location; P07 does **not** silently rewrite the user's prompt. This is soft prediction blending, not hard object-count enforcement, hard mask-based inpainting or guaranteed positional attention. The new path is validated with PyTorch fake predictors, not real GPU imagery; evaluate it separately from the first successful output before accepting regional composition.

## P07 real Anima/WAN VAE decode and canvas integration repairs

**Real installed evidence:** User's Anima CyberRealistic/Q4 run finished 144 region/window prediction evaluations and entered `decode_begin`, but Forge's native `backend/patcher/vae.py:tiled_scale_multidim` was decorated with `@torch.inference_mode()` while `VAE.process_output` subsequently called `image.add_(1).div_(2).clamp_(0,1)` on the returned inference tensor **outside inference mode**, throwing `RuntimeError: Inplace update to inference tensor outside InferenceMode is not allowed`. P07 now executes the **whole native** `vae.decode_tiled` call inside `torch.inference_mode()` for both Anima and SDXL, allowing Forge's own postprocess to operate within its intended tensor lifecycle. No global monkeypatch or copied VAE decoder. Regression actually creates an inference tensor under an inference-mode helper, reproduces the upstream exception, then asserts successful Anima 5D/SDXL 4D decode paths and unchanged propagation of other native errors. This proves the specific failure mechanism offline, **not** a completed installed GPU image.

**Canvas previously falsified actual work:** The HTML prototype drew a fixed 4×3 SVG grid, irrespective of resolution, tile or overlap; the backend used full-coverage `TilePlan._starts` with a final edge window and overlaps. Canvas now computes exact pixel-space-equivalent windows using the same algorithm and displays the real number of tiles. E.g. 2048×1536, 512px tiles, 128px overlap gives 5×4 = **20** windows; 768px tiles gives **9** at 128 overlap; 512px tiles with 192 overlap gives **30**. For extremely dense 16k canvases the overlay draws sampled outlines to preserve browser responsiveness but always shows the exact **total**. The context halo is read context, not a separate tile core.

**Editor settings were inert:** `openAdvanced` hard-coded steps=30, CFG=4.5 and discarded edits; `openGenerate` sent only model/strategy/dimensions/tile. That was inconsistent with the separate Gradio form's 20-step default, and could silently run different settings from those seen in the editor. The advanced modal is now backed by persistent `settings` in browser storage and validates steps (2–100), CFG (0–30), overlap/halo, seed, CPU workspace and tile-window MiB; any valid change survives reopening and page refresh. **Every** generation value is also sent in a strictly validated, single-use `coherent-diffusion-generation` JSON settings envelope separate from the CRF. This is necessary because the mounted Gradio 4 reactive dropdown may ignore direct DOM value updates: the initial stronger browser test caught Anima selected in HTML but SDXL received by Python. The Gradio Python callback applies this envelope atomically for editor submissions and clears it in its third output, so later native-form Generate submissions use their own values. The editor also updates visible Gradio inputs when supported, but **never trusts DOM changes as the backend source of truth**. Browser/Gradio tests verify the actual Python callback receives the exact family, dimensions, overlap, halo, steps, CFG, seed and memory settings, without mutating the authored CRF. The false `Auto · VRAM` selector was removed because it unconditionally mapped to 512px; actual tile options are explicit (256/512/768/1024).

**Output and status:** The canvas now polls only extension-owned host Gradio components every two seconds to show current generation progress and errors, and mirrors a newly generated PNG preview into the HTML editor image view; the original full-resolution PNG is still saved to Forge outputs. Standalone editor previews remain editable but cannot infer model progress. These changes don't claim complete UI feature parity, live sampler visual quality, ControlNet/VACE effects or measured RAM/VRAM.

## Per-window generation progress and model-residency performance (P07)

For a 2048 × 1536, progressive, 20-step Anima scene with 512px tiles and 128px overlap, the target has **20 windows**. With default progressive stage segmentation, this is 20 whole-scene anchor evaluations plus 10 × 20 = 200 refinement-window evaluations before any extra regional states. A 5-region scene can require hundreds or more **sequential distinct prompt evaluations**; it is not equivalent to native 20-step txt2img and does not imply deadlock after 10 minutes. Logs show an upper bound on evaluations (may exceed actual due to zero-coverage regions); they do not invent an ETA or measured VRAM throughput.

Before this repair, the P07 callback passed **no** progress handler, and Anima regional state transitions repeatedly called Forge's `sampling_cleanup`/`sampling_prepare` for mere prompt changes, including between adjacent tiles. The safe source-backed optimization reuses the already prepared Anima patcher within the same stage when only positive/negative conditioning changes and no LoRAs, guidance/controls or different model geometry are involved. Active LoRA/control transitions and stage changes still receive full ownership/cleanup. This reduces avoidable loader thrash; the genuine sequential model forward count is unchanged.

In the **Coherent Diffusion → Live diagnostics** accordion, the status now updates every two seconds with elapsed seconds, completed and upper-bound evaluations, current stage/step/tile, and time since the last event. The bottom-right **CD live debug** panel displays the same status whenever its Gradio tab is mounted, plus timestamped `conditioning_begin/done`, `model_prepare_begin/done`, `prediction_begin/end/failure`, `step_completed`, `decode_begin/done`. Every prediction is journaled; the Forge terminal prints a progress milestone approximately every ten completed evaluations or after a slow individual call. **Stop coherent generation** is cooperative: it is checked between tiles and stages, not in the middle of a long GPU kernel or Forge-native model load. If the current operation takes a very long time, the timer continues showing how long it has been active. Do not interpret a missing ETA as failed progress.

These changes are offline-verified source patches pending installed-Forge validation; 4GB VRAM output, model loading speed, optional regional LoRAs and QoS are not guaranteed.

## Automatic live diagnostics and one-click export (P07 experimental)

The ZIP installs `javascript/coherent_diffusion_diagnostics.js` through **Forge's native extension JavaScript loader**, without a CDN or userscript. After restarting Forge Neo, a small **CD live debug** button remains available at the bottom-right of Forge, including during failures. Click it to see a continuously updated browser event timeline; click **Download logs** to obtain a timestamped JSON bundle immediately, without DevTools or opening a terminal. Events are retained in bounded browser localStorage so a page refresh does not erase the recent failure.

The **Coherent Diffusion → Live diagnostics** accordion also displays the rotating server-side journal, refreshed every two seconds using Gradio 4.40's Timer without entering the GPU generation queue. While that tab is mounted, the browser download bundles the current Python journal alongside browser Gradio event metadata. A persistent Python copy survives Forge restarts at `<Forge data directory>/outputs/coherent-diffusion/diagnostics/events.jsonl`, with a single `events.jsonl.1` rotation. Each is limited to approximately 3 MiB. The in-browser snapshot may contain fewer server entries than the full persistent journal if the tab has never been opened or polling is unavailable; use the persistent journal for complete post-mortem history.

**What is captured automatically:** Gradio queue submissions and response HTTP codes, event `fn_index` and matching config component targets when available, frontend network and JavaScript error classes, generation start/native loader/preflight/inference/completion/failure stage and elapsed time, cancellation, and the specific `fn=None` Gradio failure's backend metadata. The dispatcher probe observes and *re-raises* its original exception; no sampler changes, prompts, CRF text, tokens, headers, API session hashes, images, model file names, checkpoint paths or request bodies are recorded. Backend events rotate on disk; browser ring retains only 350 metadata records. Use a copy of the exported bundle when reporting the next failure. Only share the data you are comfortable sharing.

**Safety/recovery:** The JavaScript observer is scoped to same-origin Gradio `/queue` and `/run` routes and is non-blocking. The server probe is idempotent and catches only the exact missing-backend Gradio dispatch exception. If another extension changes those APIs, the diagnostic output might be incomplete; it is not a substitute for proving a complete model inference path.

## High-resolution memory and output architecture — P07 audit

- **GPU:** Output dimensions do not determine the largest denoiser call. The adaptive global overview is fitted to the largest selected tile *read* window. The subsequent full-resolution latent is denoised with one frozen global field per sigma and sequential GPU tile calls; work and runtime increase with region count, dimensions and steps. Native Forge activation estimates are separate from our latent-window byte estimate; real 4 GB VRAM remains unverified.
- **CPU:** The global denoiser currently uses float32 full-canvas latent, accumulated predictions and weights. User-configured CPU/window MiB budgets still enforce real finite buffers; exceeding RAM is not solved by sequential GPU tiles. The core global latent is **not yet disk-backed**. Native Forge tiled VAE decode also constructs full CPU image buffers and may require substantial additional RAM at very large sizes; it is not a streaming disk-backed image decoder.
- **Regional scenes:** Removed the independent P06 fixed latent-pixel cap and 16-regional-state default. Region masks remain bounded by the existing explicit memory-workspace check and CRF schema. More active regions increase per-tile prediction calls and memory.
- **Image delivery:** The full generated PNG is saved atomically under Forge's `outputs/coherent-diffusion/`. The browser shows a bounded preview instead of embedding the huge full PNG or refusing output over 64 MiB. The original save path appears in execution evidence. Ensure enough free disk space; successful on-disk output for very large images is not yet live-proven.
- **Geometry:** Current CRF v1 and browser editor allow at most 16,384 per side. This is a product representation limit that must be lifted for larger requested scenes; do not describe it as a hardware cap or claim unrestricted-resolution inference.

This prevents the user-reported false `Anima whole-scene anchor exceeds pixel budget` failure, but **does not verify that the user's Anima/Q4 model completes actual high-resolution inference or tiled VAE decoding**. Native model-loading, RoPE, text encoding, CUDA kernel memory, LoRA hook interaction, image quality and measured VRAM/RAM remain live P07 acceptance gates.

## Current constraints

Generation is opt-in, batch size 1, editor/CRF-supported output sizes 256–16,384 pixels per dimension in multiples of 64, and 256–1024 px 64-aligned tile sizes. There is **no fixed global-overview pixel ceiling**: progressive Anima and SDXL automatically increase the overview downscale factor until its entire scene fits one user-selected inference-read window (with Anima DiT patch alignment), while the final target retains its full dimensions and all synchronized tile steps. The resulting low-res overview is a composition guide, not a promise of native full-resolution global attention or subject fidelity. 16,384 is the current CRF v1/editor representation limit, not a GPU limit; larger scenes require a schema/UI extension and finite buffer/disk planning. A validated CRF ZIP is required for painted masks. Automatic model downloads, arbitrary third-party prompt hooks, source Hires Fix/img2img processing, checkpoint resume, regional text-encoder LoRAs, native external control model loading and unverified non-Euler schedulers are not supported. External shared LoRA patch ownership remains unverified. The parent-panel image is a result preview; the source document is not automatically embedded in the PNG. Hash/seed/geometry/forward estimates are reported in the JSON evidence area, not measured GPU performance. A user must independently export the original CRF ZIP for replay.

Python offline checks and Gradio/Chromium tests are **not** proof that the user's installed Forge/Q4/GPU paths work.
